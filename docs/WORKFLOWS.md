# Running an analysis

Install from the repository root with `python -m pip install -e '.[dev]'`.
Run commands from that directory. Use a new output tag for each comparison.
Configuration paths in the checked-in files are examples from the analysis server;
change input, geometry and output paths for your machine.

## Real AmBe data

Copy `configs/data_ambe2v4_all28_box.yaml`, set the input directories, campaign,
output tag and IC bounds, then run:

```bash
ambe data process --config configs/my_data.yaml --selection box
ambe plots basic --config configs/my_data.yaml
ambe plots combined --config configs/my_data.yaml
ambe plots heatmap --config configs/my_data.yaml
```

`data process` reads waveforms and BeamCluster files, performs the IC gate and
second-pulse veto, applies the event cosmic veto, and selects neutron clusters.
`ambe data eff` is an alias for exactly the same command. There is no separate
efficiency implementation in `eff.py`. The interactive processor main is retired;
its campaign, tree, directory, waveform-sample and IC-plot options are in `stage1`.

The processor writes to `TriggerSummary/` and `EventAmBeNeutronCandidatesData/`
relative to the working directory. Plot/MC products use `output_root/run_name/`.
Changing `output_root` does not relocate the processor's CSVs. Point `inputs` in
the plotting config at the actual CSVs. `stage1.tag` names processor files;
`run_name` names the downstream product directory. Keep both distinct from earlier runs.

For MVA, use the all28 MVA config with `--selection mva`. Supply previously scored
parquets and the frozen model's threshold. Box and MVA share the waveform gate,
event veto and closed 2–67 us delayed window; MVA replaces the PE/CB/hits criteria.
Missing scores count as rejected in the existing implementation and are reported
as missing coverage. Compare on matched covered triggers before interpreting a drop.

The raw trigger fraction `unique_neutron_triggers / ambe_triggers` is distinct from
the background-corrected efficiency fit. For the latter, use `ambe stats efficiency`
and `ambe plots efficiency` with `data_ambe2v4_effpair_box.yaml`. See the fit module's
CLI help and existing efficiency reports for the source/background model options.

## MC and OPTICS

```bash
ambe mc process --config configs/cc_neutrino_v3_truthtag.yaml
ambe mc optics --config configs/cc_neutrino_optics_sweep10.yaml
ambe mc features --config configs/cc_neutrino_v3_truthtag.yaml
ambe mc mva --config configs/cc_neutrino_v3_truthtag.yaml --method clusterfinder --no-nn --save-model
```

These commands illustrate the stages, not a single interchangeable config: the
sweep config reads the parquet sample named by its own `run_name`. Process that
sample first or use an existing matching extraction. `optics` contains a parameter
grid; `features` contains the one chosen setting. The two CC event selections have
separate `cc_stream` values and outputs. See [config guide](../configs/README.md).

MVA implementation: `src/ambe/mc/mva_analysis.py`, beside `cc_selection.py`,
`cluster_features.py` and `optics.py`. The config-free scoring form is:

```bash
python -m ambe.mc.mva_analysis --score-data features.parquet --model model.pkl
```

For AmBe MC in the data-style candidate pipeline, use the `stage1_mc` configs:

```bash
ambe data processmc --config configs/mc_ambe_qe150_box_vetoon.yaml --selection box --cosmic-veto on
```

There are no waveforms in that path. The veto-on/off samples and scored tables must
match. Capture-time plots use `ambe plots basic`/`combined`; shared presentation fit
helpers live in `ambe.stats.capture_time`. The removed `mc/basic_plots.py` and
`mc/wcsim.py` were hardcoded ROOT plotting drivers with import-time execution, not
live CLI dependencies. Their former raw-ROOT invocation is not a supported interface.

## Presentations and diagnostics

The repository root no longer holds the Python utility collection. The full list
and purpose of every moved script is in [scripts/README.md](../scripts/README.md).

```bash
python -m scripts.presentation.boxcut_v4_campaign --do captureheat
python -m scripts.presentation.boxcut_v4_special --do diag
python -m scripts.presentation.collect_presentation_plots --do check
python -m scripts.presentation.collect_presentation_plots --do build
```

Builders read existing analysis outputs; the collector copies them into decks.
Only README inventories are tracked under `PRESENTATION_PLOTS/`; figures are generated
artifacts. The folder is useful as an export destination, not as an analysis dependency.
Existing images were not regenerated by this cleanup. Rebuild them after running the
analysis on your data; plot numbers may change when removed slots are omitted.

Deck 5 now reads the same waveform feature tables for its summaries and distributions.
It uses the processor's event selector for the gated summary and the shared box
component masks for cluster-only cutflows. The latter intentionally show clusters
before an event veto. Features are now IC, baseline and baseline sigma; fprompt and
its diagnostic panels are retired. Old feature files are checked against the configured
IC selection before use. Source/no-source and dummy-trigger plots remain separate.

The default PE/CB view is 0 to `cuts.pe_max + 20` PE and CB 0.1–0.5, for both box and
MVA. This is a display range, not an added MVA cut; values outside it are not drawn.

## Comparing the two cosmic-veto orderings

The old loop could save a neutron candidate before reaching a later vetoing cluster.
That event then contributed to the numerator while being subtracted from the denominator.
The current default checks the whole event first. This cleanup retains that default
and the explicit `stage1.legacy_ordering: true` reproduction option.

Process identical files and IC gates under two new tags, with
`stage1.dump_event_index: true`; set legacy ordering true for one and false for the other.
Then compare the event indices:

```bash
python -m ambe.diagnostics.compare_veto \
  --legacy TriggerSummary/EventIndex_legacy_6265.parquet \
  --current TriggerSummary/EventIndex_current_6265.parquet \
  --output TriggerSummary/veto_comparison.csv
```

The tool checks identical `(run, eventTankTime)` cohorts and veto decisions, rejects
duplicates, and reports losses for one versus multiple accepted clusters, as well as
the original single/multiple categories. The denominator stays `total_events - cosmic_events`;
only leaked numerator entries disappear in an ordering-only comparison. `numberOfClusters`
is the total before selection, so an event with one accepted cluster can still belong
to the original multiple category. Loss of a truly single-cluster event is not expected
from this ordering fix alone.

No numerical loss or explanation of the reported ~10 percentage-point MVA gap can be
established without matched data. Refit the source/background efficiency after comparing
the indices; the reported raw candidate-fraction change is not that fitted efficiency.
To reconsider removing the veto entirely, compare veto-on/off on independently validated
signal/background samples and use a denominator and background model appropriate to each.
Cluster classification alone does not establish event-level cosmic rejection.

## Retained studies

| Module | Purpose and overlap |
|---|---|
| `mc/cluster_discrimination.py` | Truth-enriched CF features and trial discrimination strategies; overlaps feature diagnostics but retains a distinct strategy comparison. |
| `mc/cluster_matching.py` | Truth-neutron matching, split/merge/missed outcomes and provenance; root multiplicity scripts were plotting adapters, not equivalent truth matching. |
| `mc/hit_accounting.py` | Reconstructed/DirectParent/CF hit counts, truth composition and unclaimed-hit diagnostics; distinct from cluster feature extraction. |
| `mc/hit_time_windows.py` | Hit timing relative to the dominant neutron/cluster, category-separated windows; overlaps older timing exploration but includes CC provenance categories. |
| `clustering/optics_data.py` | Older spatial CSV-hit OPTICS path, still called by `run_waveform_gated_optics.sh`; retained, distinct from the MC grid sweep. |
| `clustering/optics_analysis.py` | Companion comparison of those CSV labels; retained for review. |

All four MC studies still have CLI registrations. Their invocation frequency cannot be
inferred from source history. `runtable` had a live CLI and recent run-comparison references;
it is now under diagnostics. It requires one run per source position in each tag.
`icscan` now lives under plots; the old `ambe data icscan` spelling remains an alias.
The former single Python script under `scripts/` studied background-template uncertainty;
that directory also had two shell launchers. The study now lives in `ambe.diagnostics`.

No tracked `Michel_tuning.py` or `src/ambe/data/analysis.py` exists in this checkout.
The deleted `analysis_run.py` was the legacy script-era driver. See
[Michel selection notes](../michel/README.md) for the actual scripts present here.
